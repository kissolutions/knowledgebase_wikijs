# Project Status Log template

The [Project Status Log Standard](../../governance-and-doctrine/project-status-log-standard.md) requires one continuous log for **every** framework project, independent of domain plugins or registers.

1. Copy [PROJECT_STATUS_LOG_TEMPLATE.md](PROJECT_STATUS_LOG_TEMPLATE.md) into approved project storage as `project-status-log.md`. Add it to the project's working file inventory alongside the other project files. Do not populate this public template.
2. Replace placeholders and list the project's actual deliverables, with exact filenames, versions and project-relative paths. Mark absent, unknown and nonapplicable items explicitly. A PER, EDP, BOM or any other particular deliverable is not required by this template.
3. Keep Current state current. After every session changing a deliverable, update that block and append a dated entry identifying every changed file/version. Add decision-only entries when needed. Keep history oldest first and newest last; correct earlier entries through a later correction.
4. If adopting mid-project, reconstruct earlier history from identified change notes, register change logs and handoff documents. Label the back-fill, sources, event dates, reconstruction date and gaps. Append history discovered after adoption without rewriting existing entries.
5. Include the complete log in every project archive package and its file inventory. Check listed versions against packaged files; preserve each issued archive unchanged.

Existing record IDs may be cited, but the log has no required link field or structural dependency on a PER or another domain document. Detailed register records and register edit histories keep their existing authority. Handoff and status snapshots feed the log; they do not become parallel maintained records.

Template version: **1.0** (2026-11-22). The project copy keeps one stable filename throughout its life; record deliverable revisions inside it rather than creating a replacement status log at each revision.
